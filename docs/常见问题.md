# 常见问题

按"你现在看到什么"查，每条都给排查顺序。查之前先跑这一句，能定位一半问题：

```bash
curl -s http://127.0.0.1:8765/ping
```

- 有 JSON 返回 → 桥活着，问题在源或配置，看第 4、5、6 节
- `Connection refused` / 无响应 → 桥没起来，看第 1、2 节

---

## 1. 双击 `启动工作台.bat` 没反应，或黑框一闪就没了

按顺序查：

**① Python 装了吗**

```cmd
python --version
```

没有输出版本号就去 https://www.python.org/downloads/ 装，**安装时勾选 "Add Python to PATH"**。

**② 端口 8765 是不是被占了**

```cmd
netstat -ano | findstr "127.0.0.1:8765"
```

有 `LISTENING` 说明桥其实已经在跑 —— 那就不用启动第二个，直接开 `http://127.0.0.1:8765/`。要重启就先结束它：

```cmd
taskkill /PID <上面最后一列的数字> /F
```

**③ 手动跑一次看报错**

黑框一闪就没，是因为 `pythonw` 不显示错误。改成在命令行里跑，把报错打出来：

```cmd
cd /d 你解压的目录
python job_bridge.py
```

常见报错对照：

| 报错 | 原因 |
|---|---|
| `ModuleNotFoundError` | 用错了解释器，或者文件没解压完整 |
| `Address already in use` / `10048` | 端口被占，见 ② |
| `UnicodeDecodeError` | 文件被别的编辑器改存成了 UTF-8，`job_bridge.py` 必须是 UTF-8，`.bat` 必须是 GBK |
| 什么都没输出就退出 | 杀毒软件拦了。把目录加进白名单，或换到 `D:\` 下再试 |

**④ 路径里有特殊字符**

解压到 `C:\Users\你的名字\Desktop\新建文件夹(2)\` 这类路径一般没问题，但**别放在 `C:\` 根目录**、也别放在会同步的网盘目录里（OneDrive 的按需下载会导致文件读不到）。

## 2. 浏览器打开了，但是白屏 / 打不开

**必须通过 `http://127.0.0.1:8765/` 打开，不能双击 HTML 文件。**

直接双击走的是 `file://` 协议，浏览器会按跨域策略拦掉所有 `fetch`，页面能显示但一条数据都抓不到。

如果 `http://127.0.0.1:8765/` 打不开：

- 确认 `job_bridge.py` 和 `兼职匹配工作台.html` **在同一个目录**
- 确认桥的窗口/进程还活着（第 1 节 ②）
- 浏览器开了代理/VPN 时，`127.0.0.1` 也可能被代理接管。把 `127.0.0.1` 和 `localhost` 加进**代理例外**，或者临时关掉代理

## 3. 右上角显示「数据桥 未通」或黄色

点一下那颗胶囊就是重新检测，检测完把鼠标悬停上去，标题里会逐个列出每个源的状态和失败原因。

| 显示 | 意思 | 怎么办 |
|---|---|---|
| 数据桥 未通（红/灰） | 连不上本机服务 | 看第 1 节 |
| 正常 · 3 源 · 1 未通 | 桥通了，有源没就绪 | 看第 4 节 |
| 正常 · 4 平台 | 全就绪 | 没事 |

## 4. BOSS直聘 一直显示「未通」，但我明明登录了

这是最常见的一个。原因通常是四个，按顺序排查：

**① 是不是登录在另一个浏览器里**

桥用的是**专用 profile**（`%LOCALAPPDATA%\boss-bridge-profile`），和你平时用的 Chrome 不共享 cookie。你在日常浏览器里登录了，桥这边仍然是未登录状态。

**② 正确做法：点页面里的按钮**

页面「04 平台」卡片底部 → 点「**扫码登录 BOSS**」→ 屏幕上会弹出一个浏览器窗口 → 用手机 BOSS App 扫**那个窗口里**的二维码。

不要扫手机上收到的、或别的页面上的码。扫完窗口会自动保存登录态，卡片由黄变绿。

**③ 窗口没弹出来**

可能已经有同一个 profile 的 Chrome 在后台跑着（macOS/Linux 用 `ps aux | grep boss-bridge`，Windows 用任务管理器看有没有 `chrome.exe` 带这个 profile）。把那些窗口关掉，再点一次。

**④ 登录了还是未通：登录态过期**

BOSS 的登录态一般几周会过期。表现为：之前绿的，突然变黄。重新点「扫码登录 BOSS」再扫一次即可。

> 排查时别反复点「重新检测」。检测只读 cookie、不发业务请求（这是刻意设计的，否则会把一次性 token 用掉），所以它会显示真实的登录态，不会骗你。

## 5. 抓到 0 条 / 结果很少

先分辨是"没抓到"还是"抓到了但被筛掉"：

```bash
curl -s "http://127.0.0.1:8765/search?q=剪辑&city=杭州&limit=10&sources=shixiseng"
```

看返回的 `stats` 和 `errors`：

- `stats` 里是 0 → 真的没抓到，看下面
- `stats` 有数字但页面显示 0 → 是筛选太严，跳过本节目录看第 6 节

**没抓到的常见原因：**

1. **关键词太窄**。「短视频剪辑（口播方向，需会 AE）」这种抓不到东西，换成「剪辑」「短视频剪辑」这种两三个词的组合
2. **城市名不对**。58 只认城市缩写，桥里内置了 36 个主要城市；没收录的城市会抓空。试试换成「杭州」「上海」这类大城市验证一下
3. **当天的确没岗位**。凌晨、节假日、冷门岗位类型，在架量本来就少
4. **某个源被限速**。`errors` 里会有说明。等几分钟再跑，别连续重试

**验证四源是否都通：**

```bash
curl -s "http://127.0.0.1:8765/search?q=兼职&city=杭州&limit=8"
```

四个源的 `stats` 都大于 0 才算全通。

## 6. 抓到几十条，出来只有 3 条

这是正常行为，不是 bug。中间有三道闸门：

| 闸门 | 会筛掉什么 | 怎么放宽 |
|---|---|---|
| 时段冲突 | 和你勾的空闲时间对不上的 | 多勾几个时段 |
| 时薪下限 | 折算后低于你填的数字 | 把「最低时薪」调低或留空 |
| 拒绝类型 | 命中你填的雷区词 | 删掉几个雷区词 |

另外，模型判定为「不匹配」的会进「已拦截」，那里**每一条都给理由**，可以点开看是不是误杀 —— 如果理由是"没有 JD 正文"，说明那一源的详情页没取到，属于数据问题不是判定问题。

## 7. 点「测试连接」报 CORS / 跨域错误

个别模型服务商没放行浏览器直接调用（不发 `Access-Control-Allow-Origin`）。这不是你配错了。

三个办法，从简单到麻烦：

1. **换一个通道**。DeepSeek、Kimi、通义千问、火山方舟、硅基流动都支持浏览器直连，换一个能用的就行
2. **用「自定义 OpenAI 兼容」**，填一个支持跨域的网关地址（比如你自己的中转服务）
3. **本地起个反向代理**（麻烦，一般不需要）

> 注意：Key 只存在你本机的 `localStorage` 里，直连服务商，不经过任何第三方服务器。报错时浏览器控制台里能看到具体是哪个域名被拦。

## 8. 页面上的数据会不会被上传？

不会。所有数据（画像、结果、跟进存档、配置）都存在浏览器的 `localStorage` 里。

只有两处会离开本机：

- **抓岗位**：请求发往招聘站（本机 → 网站）
- **模型打分**：候选岗位的文本会发给你自己填的那个模型服务商

结果一条都不会上传到任何"我们的服务器"—— 这个项目根本没有服务器。

## 9. 想把数据清空重来

打开浏览器控制台（F12 → Console），粘这一行：

```js
['pm_v3_input','pm_v3_data','pm_v4_saved','pm_v4_ignored','pm_plat_on']
  .forEach(k => localStorage.removeItem(k));
location.reload();
```

只清结果、保留画像和配置：删 `pm_v3_data` 和 `pm_v4_saved` 两个就行。

## 10. 怎么彻底关掉服务

**Windows**：任务管理器 → 详细信息 → 结束 `pythonw.exe`（或 `python.exe`）

**macOS / Linux**：在跑 `job_bridge.py` 的那个终端按 `Ctrl + C`

关掉服务后页面就打不开了，这是正常的 —— 页面本身就是由这个服务托管的。

## 11. 杀毒软件报毒

`启动工作台.bat` 会启动一个本地 HTTP 服务并自动打开浏览器，这个行为模式和一些恶意程序相似，可能被启发式规则误报。

处理：把整个目录加进白名单。如果不放心，可以自己读一下 `job_bridge.py` —— 它只监听 `127.0.0.1`（不是 `0.0.0.0`），外网访问不到。

---

## 12. 页面显示的时间不对 / 显示「暂无数据」

- 时间来自你电脑的系统时钟
- 「暂无数据」表示还没有跑过匹配，或者结果被清掉了。点左下角「开始匹配」

## 还是解决不了

开 issue 时请附上这三样，能省掉一半来回：

1. `curl -s http://127.0.0.1:8765/ping` 的完整输出
2. 失败那次的运行台日志（页面上「运行台 / 任务单」里的文字，全选复制）
3. 你的系统版本、Python 版本、浏览器版本
